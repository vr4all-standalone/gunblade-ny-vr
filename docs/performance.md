# Gunblade NY audio and native-speed investigation

The user played the initial Quest 3S build and accepted its stereo 3D, but reported severe crackling and possible slowdown. The first audio-performance update produced only a small perceived improvement. The user subsequently clarified that their latest positive listening feedback referred to TeraBurst, not the latest Gunblade NY build. That feedback is not Gunblade audio acceptance; its next listening test remains pending.

## Measured baseline

The SDL stream negotiates 48 kHz stereo with 512-frame callbacks. During active gameplay it receives about 38,000–41,000 frames per wall second while playback requests about 48,000–49,000. Reports contain roughly 7,360–10,240 missing frames per second, often with more than 50 underrun callbacks. Five-second native-time reports exclude paused wall time and show about 82–88% speed, dropping to 74–77% in a heavier section. Headset submission at 72 Hz does not establish native game speed.

This is measured producer starvation. MAME synthesizes approximately 960 audio frames per 20 ms of native time at this sample rate. When native simulation falls behind, playback still consumes real wall time. Increasing an SDL latency option does not repair the deficit: this SDL backend ignores that option. Gunblade's 68000/SCSP path produces audio; its SHARC is a geometry coprocessor.

A deterministic 70-native-second Windows comparison now checks the untouched engine against the current engine with VR capture, a diagnostic ready host and the guarded raster shortcut. Both generate exactly 3,360,001 stereo frames at 48 kHz, with identical PCM SHA256 `48a1b9f4e292e7bf06de7f77258e72b298d7be97d88b6145b7f0587c5376d1f2`. Peak absolute sample value is 7,925 and neither has clipped rail samples. All fourteen timed work-RAM checkpoints are byte-identical. Both processes exit zero without Lua errors. This rules out an introduced synthesis difference or source clipping in this route; it does not establish real-time Android playback. Private evidence is `research/audio-audit/desktop-audio-comparison.json`.

The cumulative native-deadline pacer already matches the accepted Carnevil implementation. Carnevil's earlier problem combined spare unthrottled capacity with unnecessary sleeping; the same explanation has not yet been established for Gunblade. Controlled unthrottled versus paced runs and scheduler measurements are the next diagnostic if the geometry savings are insufficient. Sibling board-specific CPU shortcuts and RAM addresses must not be copied.

It now clips one candidate at a time and stops at the first visible nondegenerate window-1 world triangle. The resource, reference, service, framebuffer and invalid-scene guards are unchanged. The paced run records 2,017 guarded CPU raster skips, 1,987 native non-playing paths and 23 direct framebuffer paths. Full hardware speed and audio remain unresolved.

A 7,993-sample native CPU profile, with zero lost samples, identifies scheduler timeslices, i960 instruction execution, billboard Z80 execution, sound DSP work and native rendering among the costs. It is a late-stage sample that includes the transition back to native raster fallback, so its raster percentages must not be generalized to the entire active stage. The 500 kHz UART clock produces a million clock-edge timer boundaries per native second; possible event batching requires exact UART output timing, interrupt reassertion behavior, reset/save-state support, and fresh paired audio/RAM proof before any production use.

## Verified native timing refinement

Patches 0009 and 0010 batch quiet UART clock edges while retaining the 500 kHz clock phase, idle transmit-ready callbacks, the original absolute 1 microsecond CPU scheduling boundaries, timer-head abort behavior and outer-loop cadence. The first prototype without the scheduling correction changed native audio/RAM and was rejected. It was never installed.

The revised Windows gameplay pair matches its WAV, all 138 snapshots of work/extra/backup RAM, all 46 native images and per-frame game events byte for byte. A service pair matches another 63 RAM snapshots, 21 images and WAV. An independent test performs two actual saves and restores per variant around native UART preparatory/terminal boundaries: its WAV, 99 RAM snapshots, 33 images, lifecycle times, materialized UART state and 21 boundary status reads match. Unmaterialized lazy clock-state differences are retained and classified in the private report, not hidden. Injected pin transitions, direct callback insertion traces and Quest save/load remain outside this coverage.

The actual ARM64 70-second reference/coalesced pair also matches WAV, all 213 RAM snapshots, all 71 native images and per-frame events. Coalescing is positively observed in the scoped MAME log: 5,695,545 timer events represent 70,006,994 virtual edges. Measured stage speed rises from 82.1941% to 85.4762%; full native speed remains unresolved. Both runs use the same strong-function local binding described below. Evidence is `uart-v2-quest-comparison.json`, `uart-v2-gameplay-comparison.json`, `uart-v2-service-comparison.json`, and `uart-save-proof/comparison-classified.json`.

The Android link binds defined non-weak functions locally. An unmodified control relink reproduced the accepted original library byte for byte; comparison preserves dynamic symbol metadata, weak and object bindings, all imports, SONAME and dependencies. SDL/JNI and C++ runtime imports remain dynamic. A separate linker-only Quest pair matches PCM and 14 work-RAM snapshots, with a small measured stage change from 80.7377% to 81.4463%. This is not independently sufficient for full speed.

The canonical combined ARM64 engine SHA256 is `5b771d61f0a59bac87d0fedf7864bad47a27683d99539bb42cc01d9c45c81f6f`, exactly matching the tested private relink. The Android launcher now enables the verified UART policy; Windows leaves it opt-in. `GUNBLADE_UART_REFERENCE` forces original clock behavior in diagnostics. Built-in frame skipping was investigated but remains unchanged: it discards real world updates and odd direct-framebuffer banks, despite preserving native audio and RAM in the tested runs.
