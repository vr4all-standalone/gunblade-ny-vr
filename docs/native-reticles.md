# Native stereo reticle evidence

The renderer retains Gunblade NY Revision A's original targeting polygon artwork and animating native lists. The host can place those polygons at each logical player's current scene aim point with `GLScene::set_reticle_targets(targets, head)`. One target position and one head orientation are shared by both eye passes. Native pixel offsets become physical offsets using the reference native presentation lens and selected panel distance; the marker's depth comes from the actual target. The native 600/600 aim projection remains separate from the world 400/400 projection.

Suppression always requires a complete positively identified native source and an active gameplay context. In-game mode additionally requires a valid replacement target; Custom and None can hide an identified native source without a target. Unknown, partial, malformed and rejected sources are preserved. Boot and service stay native when the host disables gameplay context, and a full native-raster fallback remains intact because its reticle pixels cannot be safely isolated. The host controls gameplay, focus, menu, tracking and player-life eligibility independently of the laser beam setting. Identified native reticle polygons are excluded from cached scene aiming so a gun ray reaches the scene behind its own visual feedback.

## Reticle modes

`GLScene::set_reticle_mode(ReticleMode, gameplay)` supports `In-game`, `Custom` and `None`; invalid values normalize to In-game. In-game preserves the original native artwork and animation. Custom renders four separate diagonal vector arms in solid red for P1 or blue for P2. The original outer silhouette and empty aiming gap remain, with no black/white interior bands to shimmer as they shrink below a pixel at distance. None draws no marker and hides only positively identified native marker polygons, including when a controller has no tracked target. The host independently removes auxiliary gameplay endpoint dots for Custom and None while retaining menu/service pointers.

Custom uses the existing minimum-size and shrink-distance policy, the same shared head orientation, and the actual per-player 3D target. Its initial angular envelope approximates the original 56-source-pixel artwork at focus 400. It does not require native reticle artwork or material resources and can be shown over a native-raster fallback; unknown original raster reticles remain intact because they cannot be positively isolated. These are original vector primitives without image assets.

Source object identity, complete counts, materials, native link attributes, focus, center, uniform planar transform and matching per-player gun origin are all checked. Position, color, focus or window alone never authorize suppression. The audited Revision A native code explicitly submits P1 lists `0x80cb22` and `0x80ccac` at i960 `0x71358` and `0x713d8`, after setting focus 600 at `0x71270..0x71280`; it restores world focus at `0x71400..0x71418`. The corresponding source table at `0xaf6c8..0xaf70c` independently records the ring/chevron lists and 19/11 counts.

The renderer groups each player's known native source IDs by their actual submission window and checks every group for the complete 19/11 structure and all identity rules. The highest group supplies relocated artwork only if every other known-source group is a complete verified duplicate. A partial, foreign or mismatched group keeps all native artwork for that player. Material, source, depth, origin, UV, viewport, native sort and cull flags remain exact. Repeated in-plane rotation coefficients allow at most two float32 ULPs, and transformed X/Y must project within .01 native source pixel; the later capture evidence below establishes why byte equality is too strict. Mission selection remains native through the host's gameplay-context gate.

The 30 submitted pieces include eight culled strip connectors, leaving 22 visible pieces per player. `model2_state::check_culling` in the pinned engine's `src/mame/sega/model2_v.cpp:246` rejects link type zero before viewport clipping. The culled reticle pieces have attribute `0x20401`; the visible pieces use `0x20601`, `0x20502` and `0x20602`. All have positive Z 10 and double-side enabled. Relocation therefore preserves those connector culls and reconstructs complete visible polygons without the cabinet viewport crop. It does not restore the culled connectors.

## Distance readability and act-two follow-up

The user subsequently accepted the first-act native reticles, performance and angle on the installed build, and requested larger reticles at distance. The next source revision scales the original polygon offsets by `1.35 * max(panel_distance, distance(target, shared_head_position))`. This makes the near reference size 35% larger and prevents distant artwork from shrinking below that angular size. The reticle remains at its actual target position and depth. It uses the original vector polygons, materials and animation; no bitmap enlargement is involved. A real OpenGL regression verifies readable artwork at eight metres while retaining the corresponding 3.2-source-pixel stereo disparity for a 64-mm eye separation.

The user also reported flat native reticles and poor performance in level-one act two. That report is not treated as evidence that a particular identification check should be relaxed. `GLScene::reticle_diagnostics()` now exposes the prepared frame's sequence, rejected count, resource/geometry usability, unknown focus-600 count, and each player's known-source counts by window, selected/visible/duplicate counts and rejection flags. The flags distinguish frame/display/resource/geometry failures from missing source/top window, incomplete parts, native links, materials, focus, center, transform, origin, vertex and duplicate mismatches. `GLScene::prepared_frame()` returns the matching immutable owned snapshot for bounded opt-in capture by the host.

The enlarged-marker replay is retained separately in `research/stereo-native-reticle-readable/report.json`: all 40 disabled-target images remain byte-identical to the frozen baseline. In sequence 2015 the larger P1 marker contributes 1517/1518 left/right changed pixels and P2 contributes 778/771, with zero differences outside the projected native marker footprint. The previous proof remains intact as the before-size-change result.

The bounded 240-native-second production autoplay run then captured a concrete recognition failure, retained in `research/act2-autoplay-20261029-a/captures/`. At 80.157624, 80.331464, 80.470536, 84.903456 and 210.033488 seconds, full known native reticle lists were rejected by the original byte-exact duplicate comparison. Repeated chevron rotation coefficients differ by one or two float32 ULPs (at most `1.49e-8`). Raster X/Y extraction shifts the 24-bit command left by eight bits; its quantized transformed vertices differ by at most `.0007812` source pixel in the captured pairs. Near cancellation can produce several command steps while remaining much smaller in projected pixels. Native source IDs, materials, origin, depth, UV, viewport, ordering and cull flags match.

The revised comparison accepts only that bounded numerical difference: two float32 ULPs for the four in-plane rotation coefficients and `.01` source pixel for projected X/Y. Regressions reject three rotation ULPs, `.011` source pixel, nonfinite values, changed origin, materials and unrelated HUD. That first correction retained fixed window rules; the actual Quest area-two evidence below supersedes them.

The corrected replay report is `research/stereo-native-reticle-roundoff-final/report.json`. The original game legitimately omits P1's source in frame 4883 and P2's in frame 12081; those absences are preserved. Forty new target-disabled before/after image comparisons and the forty frozen first-act comparisons are identical. This reproduces and fixes native reticle recognition dropouts; it does not establish that the reported act-two performance problem is fixed or that the autoplay covered the user's exact route and act.

## User-tunable natural shrinking

The user subsequently preferred the original natural shrinking and requested controls to tune its minimum size and rate. The current policy removes the 1.35 near-size boost and replaces the previous 100% angular floor. `GLScene::set_reticle_size(minimum_ratio, shrink_distance)` accepts a minimum ratio from `.05..1` and a shrink distance from `.2..20` metres; nonfinite values independently fall back to `.25` and `1.8`. These initial defaults are for user tuning rather than a final accepted calibration.

For target distance `D` from the shared head pose and reference panel distance `R`, the original polygon offset reference is `R` while `D <= R`. Beyond it, perceived size is `max(minimum_ratio, 1 / (1 + (D - R) / shrink_distance))`, and the physical reference is `D * perceived_size`. A larger shrink distance makes shrinking slower. Setting shrink distance to the panel reference reproduces the original constant physical artwork size until the selected minimum is reached. Target position, depth, per-eye projection, original material and animation, and the bounded native duplicate-rounding correction remain unchanged.

Pure policy regressions cover monotonic perceived shrinking, the angular floor, slower/faster falloff, original physical scaling, removed near boost, clamp limits and invalid-value fallback. Real OpenGL checks cover default 25% far size, a selected 75% minimum in both eye passes at the same eight-metre target, and slower shrinking with a larger distance setting.

The tuning-policy native replay is retained in `research/stereo-native-reticle-tuning/report.json`. All 80 target-disabled reference comparisons remain byte-identical. Every present native source in the eight later captures remains recognized, legitimately absent players remain absent, and replacement drawing changes no pixels outside the projected original-polygon footprint. The initial physical artwork size is restored for the hand-checked two- and 2.8-metre replay targets within the three-metre reference panel. No headset test is implied by these checks.
