# Gunblade NY platform delivery

Development application ID: `com.vrlightgunhub.gunbladeny`. Quest 3 and Quest 3S use Android ARM64, API 29 minimum, NDK 29.0.14206865 and the OpenXR loader. Windows uses AMD64 and the user's active OpenXR runtime. Native components are `gunblade.exe`, `gunblade_xr.dll` and `libgunblade_xr.so`; the engine subtarget is `gunblade`.

The preferred Quest folder is `/sdcard/Android/data/com.vrlightgunhub.gunbladeny/files/roms/`, owned by this app and readable without all-files access. Open setup once to create it, then place owned original Revision A media there. One complete `gunblade.zip` containing all 18 manifest payloads works; a split set also uses `segabill.zip` in the same folder. Downloads remains an optional source only after the user grants its broader file access manually. Windows uses the delivery's `roms/` folder. No CHD is used. Android validates payload size, CRC32 and SHA1 before launch. No commercial media or capture data is included in software packages.

The gun selector exposes Arcade and Zapper. Legacy Custom selections fall back to Arcade. The installed workflow does not require all-files access.

Hold the trigger for automatic machine-gun fire. Either A or X starts P1 initially. Once P1 is active, the assigned other player's Start joins P2; the settings menu reverses the default P1-left/P2-right hands. The port inserts a credit followed by delayed native Start. Native operator Test/Service controls select the original menus; from Exit, eight Service steps reach AIM SET. Calibration and game state belong to Gunblade NY's Model 2B input adapter.

All mutable build and signing state is private: engine checkout at `D:/VR4ALL-Gunblade-Build/engine`, Quest work and Gradle project output under `quest/`, Android host under `host-android/`, Gradle user home under `gradle-user-home/`, signing key under `private/`, and software artifacts under `artifacts/`. The Quest script reuses compiled SDL/OpenXR dependencies read-only; any rebuild of those dependencies uses this port's Quest work directory. It never configures or installs into a sibling port's cache. Private build paths reject symbolic links and junctions.

Build dependency discovery: `tools/build-quest.ps1 -CheckOnly`. A full build uses the pinned engine checkout through `-WorkEngine D:/VR4ALL-Gunblade-Build/engine`; `-SkipEngineBuild` and `-SkipHostBuild` reuse this port's compiled libraries. The Gradle wrapper always selects the private Gradle user home. The local development signing key is generated there by the Quest script and excluded from packages.

Software-only checks: `python -B -m unittest discover -s android/tests -v`. Packaging verifies ARM64 ELF or AMD64 PE headers, required libraries, archive integrity, and absence of game media, diagnostic scenes, captured RAM, private state and keys. APK signatures are verified with Android's `apksigner`; the Quest build also checks the final application ID using `aapt2`.

The optimized renderer uses one ordered world draw per eye while retaining Gunblade's native polygon scanline interpolation. The current Android audio-performance launcher enables the guarded duplicate-CPU-raster shortcut; Windows leaves it unset. `GUNBLADE_FAST_RASTER=1` requests it; the presence of `GUNBLADE_CPU_RASTER` or `GUNBLADE_SCENE_DIR` forces the original reference raster. Service, direct framebuffer and incomplete scene paths remain native. Wider View defaults on; later explicit settings are saved. See validation.md and performance.md for evidence and limits.

The latest Android timing build also enables verified UART event batching with original clock phase and CPU scheduling preserved. `GUNBLADE_UART_COALESCE=1` requests it and `GUNBLADE_UART_REFERENCE` forces the original diagnostic path. Android binds only defined strong engine functions locally; imported SDL/JNI/runtime functions and weak identities remain dynamic. Matched native ARM64 evidence passes, but sustained native speed is still about 85% in the measured stage and listening acceptance remains pending.

The user has played on Quest 3S and confirmed working stereo 3D. Audio and full native speed remain under investigation; extended controller, service, calibration and thermal coverage is incomplete. Quest 3 and Windows OpenXR hardware validation remains **untested**. Artifact metadata conservatively retains the untested development status rather than implying a full hardware sign-off. This workflow creates local artifacts and does not publish them.
